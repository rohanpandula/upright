1. METRIC RE-DERIVATION
The claimed metric is exactly reproducible. 625 fixed source samples
(25x25 mgrid including corners), Euclidean RMS in pixels / hypot(w,h) * 100,
optional per-attempt best translation + uniform scale ("shape"). Independent
code reproduced every row tested and the headline mean:
  unframed raw            33.266029 %   (matches round8 33.266029)
  framing only             3.562255 %   (matches 3.562255)
  framing + runtime scale  0.587092 %   (matches 0.587092)
  shape lower bound        0.403312 %   (matches 0.403312)
  best centre scale LB     0.430136 %   (matches 0.430136)
  naive full-rectification 50.297451 %  (matches round4 50.297451)
  naive shape LB           1.995733 %   (matches round4 1.995733)
All 80 scene/mode/seed attempts accepted. The 0.587092 figure is therefore
arithmetically correct. It is 45.6% above the 0.403312 shape bound and 36.5%
above the 0.430136 centre-scale bound: the runtime scale rule leaves real error.
Qualification A: 0.587 needs framing=True, scaling=True. Plain solve() scores
33.27%. The number is a pipeline number, not a solver number.
Qualification B: 0.403312 is the best translation+uniform-scale alignment of the
port's OWN unframed H. It is a lower bound only for those two operations, not
for a free homography, and it is computed from the same H it is compared with.
Qualification C: only ~40 distinct H exist behind the 80 attempts (2-3 unique per
5 seeds); the four "scenes" are two base poses (A=C, D=A+roll). Effective n ~40.
Qualification D: the 10/90 framing weights and the 1.10 scale switch were fitted
on these same 16 slots plus the 320 sweep slots (round8 itself says the sweep is
"NOT a blind holdout"). The 0.587 and the 0.403 are in-sample.

2. CONTROL: ADOBE POLICY APPLIED TO NAIVE FULL RECTIFICATION
Naive = K(true R) K^-1 at the true 1600 px focal, H22 normalized, then Adobe's
own framing then scale policy (same order as solve_ex), scored identically.
  condition                                   mean raw %

  naive + framing only                         6.0106

  port, framing only                           3.5623
  port, framing + runtime scale                0.5871
  port + perfect rotation (port K1, policy)    0.6009
  naive mode-aware + true rotation + policy    0.5980
The literal naive+policy control (3.1071) is 5.3x worse than the port, but that
baseline is mode-blind: full rectification is the wrong target for auto/level/
vertical. Per mode (port / naive+policy / oracle-rotation+policy):
  auto      0.9224 / 3.2891 / 0.9331
  full      0.1986 / 0.2103 / 0.2103
  level     0.9692 / 4.3963 / 0.9848
  vertical  0.2581 / 4.5329 / 0.2755
With mode semantics and perfect rotation the control is 0.5980 vs the port's
0.5871: the port is only 2.4% better than oracle geometry under the same policy.
The policy alone accounts for 98.2% of the raw reduction (33.266 -> 0.587);
geometry accounts for the rest. On full mode alone the port beats naive+policy
by 5.9% (0.1986 vs 0.2103) and beats oracle-rotation+policy by 5.9% too.
Conclusion: the headline advantage is the framing/scale policy plus mode
semantics, not solver accuracy. The solver is at oracle level, no better.

6. "SCALE POLICY REPRODUCES ADOBE TO 1e-6"
Refuted as a coefficient claim, confirmed as a raw-distance claim.
Reconstructed native maps independently (RQ of P H K0, stored source focal,
s_native = sqrt(fx fy)/f0). Scale-policy error over the 16 active slots:
  max 9.882e-6, RMSE 4.975e-6, mean 3.363e-6  -> ~1e-5, not 1e-6.
Resulting raw map distance: mean 1.083e-4 % = 1.083e-6 of the diagonal,
max 3.078e-4 % = 3.078e-6. So "1e-6" is true only when quoted as a
fraction-of-diagonal raw distance; the scale coefficient itself is 1e-5.
The 16-slot table reproduced exactly, including the 10/90 framing matrix
errors ~1e-10. V40S3 Full/Vertical still fail by 0.0466 scale (3.96% raw).
The 16 slots are the same slots used to fit the rule, so this is fit quality.

7. BOTTOM LINE
The two numbers are arithmetically correct and reproducible. The honest framing
is: "port + a policy fitted to Adobe reaches 0.587% in-sample, versus 0.403%
if the same map is given the oracle scale; oracle-geometry + the same policy
reaches 0.598%, so the solver contributes ~2% and the policy ~98%." The seed
fix, held-out score and perturbation robustness all hold. The 1e-6 claim needs
the units stated. The held-out set is frozen but no longer blind.
