ROUND 4 — FIDELITY TO ADOBE, NOT TO PERFECT RECTIFICATION — 2026-10-28
========================================================================================
VERDICT: YES, on the four available Adobe scenes and the four cached automatic modes,
the port is closer to Lightroom than a naive always-full rectification baseline.
It is NOT an exact clone. Auto still over-corrects B_strong substantially, Full retains
better geometry than Adobe, and Adobe's output framing is missing. This round improves
shape agreement but REGRESSES raw mapping agreement relative to the starting port.

1. SCOPE, ORACLES AND METRICS
All work stays inside research/upright/. No new dependency, native Adobe code, network,
image, ground-truth scene, focal calibration policy, or quality threshold was introduced.
Four adobe_truth/img_*.lua files exist. All four are scored; slots Auto=1, Full=2,
Level=3, Vertical=4. Off/Guided identity cache slots are not automatic-solver evidence.
No held-out raster has an Adobe cache here; the 70/700 geometric attempts cannot establish
Adobe fidelity. A/C are related clean/noisy renderings; these are not four independent
real photographs. Adobe is fixed cached output, not re-run for our RANSAC seeds.
The actual port, port/upright_port.py, is evaluated. Existing validate_vs_adobe.py and
compare_prototype_vs_adobe.py target upright_core.py, not this port; the former scores
geometry. Their cache parsing/slot convention is reused, not their prototype results.
Primary input: existing TIFFs, bundled detector, known generating focal 1600px, seeds
0..4. Sensitivity: the SAME images/segments with each stored Adobe focal converted by
the proven sensor-diagonal convention. This is an input sensitivity check, not tuning.
Both versions receive the same segments/prior/seed; native H never enters the solver.
80 returned mappings/version/prior = 4 scenes x 4 modes x 5 seeds; 320 paired rows total.
Rejected identities are included. No scene, slot, or failing seed is omitted.

Raw: RMS Euclidean distance between Adobe and port output coordinates for the SAME
625 source points on a 25x25 uniform grid including corners, in pixels, divided by
source image diagonal and multiplied by 100. No crop/translation/zoom is removed.
Shape: same output points after fitting ONE positive uniform output scale and a 2-D
translation from the candidate to Adobe by least squares. Rotation, shear, aspect,
and projective differences remain. This is explicitly a partial fidelity metric; it
does not establish agreement with the whole stored H. Both metrics ignore H scalar gauge.
This avoids comparing raw matrix coefficients, ground-truth residuals, or treating an
area-normalized inverse composition as a complete Adobe homography agreement score.
All sample mappings are finite and remain on one side of the projective horizon.
Naive baseline: exact K(true) R(true) K(true)^-1, applied identically for EVERY mode,
with centered K and no framing. It has perfect geometric knowledge. It is deliberately
the requested full-rectification baseline, not a mode-aware competitor. The shape score
removes arbitrary baseline output translation/zoom, so the verdict does not rest on its
poor framing alone. All scenes/modes/seeds have equal weight; seeds are not independent
Adobe observations. Small Full-only gains do not imply native Full has been recovered.

3. DISAGREEMENT CLASSIFICATION — COMPONENTS, NOT ONE LABEL FOR AN ENTIRE H
(a) implementation bug; (b) port geometrically better; (c) damping/mode semantics;
(d) port worse/incomplete. A single H can have better pitch and worse roll/framing.
Evidence used to distinguish them: native H is the fidelity target, independent world
lines diagnose axis alignment, a world X/Z horizon diagnoses roll, and controlled changes
separate damping from the full solve. A small homography distance alone proves none of these.

Shared findings:
  (a) Different undamped objectives/gates per mode: Adobe-focal A/C accepted Full but
      rejected Level (10/80 mode attempts). Fixed by using the unchanged Full objective
      for every automatic mode before damping. All 80/80 now return a valid mapping.
  (c) Auto used a branch-conditioned 14.58deg/3.56 curve on camera pitch, although the
      requested pooled 13.33deg/2.64 curve is in visible-keystone units. Fixed the
      constants and the x-axis, and converted physical convergence removal to pitch
      rotation by a bounded scalar solve. Merely replacing constants on Euler pitch
      made Auto under-correct still more; that is not the adopted change.
  (d) All modes lack native destination camera/framing policy. The port fixes destination
      principal point at 0.5/0.5; native maps include different translation, scale and
      mild shape effects. Large raw errors are retained. No empirical per-scene recenter,
      zoom, cache lookup, or invented Adobe crop policy was added. This was an explicit
      pre-existing limitation, not evidence that the two-camera algebra itself is broken.
  (c, residual) A pooled Auto response is not a native branch model. Coupled yaw/roll,
      support distribution and focal branch behavior remain approximate. The requested
      formula is implemented; exact recovery of these native choices is NOT claimed.

4. AUTO: MEASURED CURVE AND ACTUAL ADOBE UNDER-CORRECTION
Requested constants now used: sigma_V=13.33deg [9.94,22.72], L0_V=2.64, L0_H=76.73,
sigma_yaw=11.64deg, sigma_pitch_gate=22.10deg, roll_auto=0.928. Vertical x-axis is
P95-P5 signed vertical line direction spread in PIXEL angles, not Euler camera pitch.
The response is lambda/(1+lambda), lambda=2.64*exp(-keystone^2/(2*13.33^2)).
A bounded 32-step scalar inversion matches that removal fraction on selected observed
vertical supports while retaining the separate yaw and roll schedules. If a target lies
outside endpoint spreads, the pitch scale clips to [0,1]. This is our implementation,
not recovered native source. Full/guided and explicit damping= reconstruction are retained.
Observed edge fragments approximate the visible world lines used in the fit; sampling,
noise, quantile ordering and native detector differences prevent exact transfer to world lines.
The test checks physical removal on noiseless projected lines with both pitch signs.

Provenance cautions: evidence/sigma_v_precise.txt reports 80 exposed, 76 solved, 4 total
abstentions. Its keystone fit C has sigma=13.33 but L0=2.474; L0=2.638 belongs to the
camera-pitch fit A (sigma=22.26). The requested pair 13.33/2.64 is used verbatim, not
misrepresented as one jointly fitted parameter pair. The pooled fit has ~0.210 fraction
RMS error, a low-angle shoulder and high-angle branch bimodality. Its CI is not a per-image
prediction bound. No new fit or bootstrap was run; the actual stored transforms remain
the final target. The old branch-conditioned sigma evidence remains untouched.
The corpus roll extraction and the port Euler decomposition also use different rotation
conventions; independent axis scaling is consequently an approximation. Changing all mode
axes to a different convention is not justified by the physical yaw sweep or these four
matrices, and would change Level/Vertical semantics. This is an unresolved modeling limit.
