3. LINE DETECTOR

### 3.1 It is NOT stock LSD and NOT EDLines  [PROVEN]

Detector entry 0x22bd090. Object at rbp-0x2c8; defaults built by ctor 0x22be000.
Run wrapper 0x22d2250; segment-merge pass 0x22d2b60; core 0x22c6f20.

The core is a **gradient-orientation, a-contrario-validated, per-length-bin
extractor with iterative refinement**:

  * 0x22c7148..0x22c7195 computes the bin count  [PROVEN]
        n_bins = round( 4.0f * logf(max(w,h)) / -logf(8.0f) / detector[+0xc] )
        i.e. n_bins = round(4 * log8(maxdim))   (detector[+0xc] default 1.0f)
        const -4.0f        @0x338bcf0
        const -2.0794415f  @0x8e6d170  (== -ln 8)
        => ~13 bins for 1000 px, ~16 for 4000 px. These are *minimum aligned-
           point counts* per length bin, i.e. the significance threshold.
  * 0x22cae70(&hist, n_bins) called twice (two histograms, rbp-0x60 / rbp-0x90)
  * loop over bins -> 0x22cafd0(&pts,&int,&v1,&v2,n_bins, scale) extracts
    candidate point chains per bin; survivors pushed to [this+0xe8] (vector of
    0x18-stride point vectors) and [this+0xd0] (vector of 12-byte {u64,u32})
  * 0x22d0720(obj, 10, 0.00048828125f) is called in a loop capped at 0x63 = 99
    (0x22d2293/0x22d22cf) -> iterative refinement, 10 inner iterations,
    step 1/2048
  * 0x22c9b60 = finalise; 0x22c6f20 = setup/execute

Why not LSD: LSD uses 1024 angle bins, 2 directions per bin, a binomial-tail NFA
over aligned points, and no per-length binning. Here: 8-way direction
quantisation (§3.2), log-scaled per-length significance bins, and a 10-iteration
least-squares-style refinement loop. Why not EDLines: EDLines has no a-contrario
test and no refinement loop.  [INFERRED: "custom / EDLines-lineage but
NFA-validated"]

### 3.4 Minimum line length
There is **no explicit pixel min-length constant**.  [PROVEN by absence]
Length is used in exactly two ways:
  (a) significance: a chain must have > round(4*log8(maxdim)) points that agree
      with the direction within +-22.5 deg (0x22cb5e3). At 4000 px that is
      >16 points, at 1000 px >13.
  (b) weight: 0x22bd394..0x22bd505 computes each segment length, sums, divides
      each by (sum/count) so weights are mean-normalised, stored in
      [this+0x70] (vector<double>) and consumed as RANSAC/scoring weights.
So the effective minimum length is the a-contrario count, which is
logarithmic in image size rather than a fixed pixel count.  [INFERRED]

### 3.5 Two detection passes  [PROVEN, purpose INFERRED]
  pass A: 0x22bd0f1 0x22be000(obj,this+8) / 0x22d2250(obj, maxdim*scale)
          output -> [this+0x40] starts, [this+0x58] ends, [this+0x70] weights
  pass B: 0x22bd507 scale = 320.0f / (float)[this+0x3f8]  (0x8d3ab98 = 320.0f)
          -> working image becomes 320 px wide; output -> [this+0x88] as Vec3
          chains; count printed with "circle_P size = %u" (0x22bd84e)
[this+0x3f8] is the long side of the *input* image (driver 0x22ec99a compares it
to max(w,h)). Pass B therefore always downsamples to 320 px. [INFERRED: A = full
-resolution metric detection, B = coarse 320 px structural pass]

5. VANISHING-POINT STAGE 0x22d7cb0 -> RANSAC 0x22d8f20
--------------------------------------------------------------------------------
### 5.1 Normalisation  [PROVEN]
0x22d7df2..0x22d7ed1: for every segment, l = p_start x p_end (homogeneous line),
then l /= ||l|| with a 1e-12 guard (0x536d580) and an all-zero guard. Segments
are stored normalised in a scratch vector; the raw endpoints are kept.

### 5.2 Model and sampling  [PROVEN]
0x22d8f20(rdi=&out_vps, rsi=segments, rdx=starts, rcx=ends, r8=normalised
          lines, r9d=iters, stack: cfg=[this+0x468], this)
  0x22d8f88  iters = r9d  (== 2000)
  0x22d9071..0x22d90a3  two distinct indices drawn via virtual [sampler+0x20];
        the `cmp r15,rax / je` loop rejects a repeat (minimal sample = 2 lines)
  0x22d90a5..0x22d9179  model = l1 x l2, normalised with the 1e-12 guard
  => a VP is the intersection of two sampled lines. 2-point model, 2000 iters.

### 5.3 Residual and inlier test  [PROVEN]
0x22ec470(out, starts, ends, &vp, tau):
  m = 0.5*(p_start + p_end)                       (line midpoint)
  c = v x m
  r = |c . p_start| / hypot(c.x, c.y)             (0x2c51174 = hypot)
  r = min(r, tau)                                 (0x22ec69f minsd)
  all-zero v -> r = tau for every segment

Inlier test in the RANSAC (0x22d9243..0x22d92ab): `r < tau`, SIMD-counted, then
  0x22d92b9  cmp cfg[+0x08] (=3), count ; jg reject
=> **minimum 3 inliers per accepted VP**.

### 5.4 tau = sqrt(3)  [PROVEN]
The threshold is a lazily-initialised file-scope double at 0x9404638:
  0x22d7c96 / 0x22d9bd6  movabs rax, 0x3ffbb67ae8584caa
  0x22d7ca0 / 0x22d9be0  mov [0x9404638], rax
0x3ffbb67ae8584caa as double = **1.7320508075688772 = sqrt(3)**, guarded by the
one-shot byte 0x9404640. It is a *constant*, not image- or focal-scaled.
0x22d8fa0 loads it into the threshold slot.  [PROVEN value; note the residual is
already in normalised homogeneous units, so a fixed sqrt(3) is dimensionally
consistent, but it is a surprisingly loose gate]

### 5.5 Clustering = sequential multi-model RANSAC  [PROVEN]
There is no separate distance-based clustering pass; clustering happens inside
the same loop:
  - 0x22d92d0 loop over already-accepted VPs; 0x22d93a0..0x22d93c2 skip the
    candidate outright if BOTH sampled lines already have r == 0 under that VP
    (i.e. the candidate is already explained).
  - 0x22d9360 compares (count_new - 1) / (count_existing - 1) against cfg[+0x10]
    (= 1.0).  If ratio >= 1.0 -> 0x22d9562: compare SUM of residuals; replace the
    incumbent only if the new sum is strictly smaller (0x22d95bd ucomisd/jbe).
    If ratio < 1.0 -> append the new VP (0x22d94f8) and increment the counter.
  - the loop ends when iters are exhausted or the accepted count reaches the cap.
  - accepted VPs go to [this+0xe8] (3-double directions, 0x18 stride) and their
    indices to [this+0x138] (vector<int>), capped at 9 (+1 slot).

### 5.6 Selection / ranking after the loop  [PROVEN, criterion INFERRED]
0x22d8371..0x22d84d8: a pairwise tournament.
  for each candidate pair (i, j): s = sum_k M[i][k] * w[k]  (w = [this+0x70],
  the mean-normalised segment lengths); track running min xmm1 (starts at +inf,
  0x321ac40) and running max xmm0, recording the argmax with cmova r15,r11.
  If the final running max != 0, push the winner. 0x22d84d0 then moves on.
=> greedy max-of-min ("bottleneck") partner selection, i.e. the VP that is
   jointly best supported across the candidate set wins the slot.
Downstream, 0x22d3950 (estimate_init_M) builds the per-VP weighted line sums
  sum_i w_i * l_i  and 0x22e7e00 evaluates candidate M against them.

6. WHAT IS SOLID vs SPECULATIVE
--------------------------------------------------------------------------------
SOLID (read from code/constants, reproducible by address):
  - pipeline order and every stage boundary (§2)
  - detector is gradient + a-contrario, 8 directions, +-22.5 deg via
    cos(22.5)=0.9238795042037964f at detector+0x30 (§3.2)
  - significance bins = round(4*log8(maxdim)) (§3.1)
  - merge tolerances 12.0 px perpendicular / +-10 px along (§3.3)
  - no fixed minimum line length; length is mean-normalised into a weight (§3.4)
  - RANSAC: 2000 iterations, 2-line minimal sample, >=3 inliers, tau = sqrt(3),
    cap 9 candidates, count-ratio 1.0 then residual-sum tie-break (§5)
  - all defaults in the four parameter structs (§4)

SPECULATIVE / INFERRED (flagged above):
  - the "not LSD / EDLines-lineage" naming; the detector is bespoke
  - detector+0x20 = 0.0443675f role (no reader found)
  - detector+0x28 = 2 and +0x60 = 3 modes
  - pass A vs pass B purposes
  - +0x18 = 0.95 in the RANSAC config (never read by the VP stage)
  - the 0.16 = 0.4^2 squared ratio
  - "bottleneck" reading of the pairwise tournament

UNRESOLVED: no focal length is used anywhere in the VP stage; the angular
tolerances in §4.2 are dead-simple functions of the long image side, which
suggests ura treats the camera as having f ~ max(w,h) during clustering and only
recovers a real f later, in estimate_MKR / opt_H5.
